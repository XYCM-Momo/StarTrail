## 改了什么

**新功能：大地图 / 小地图设置各增加一个「显示 NPC 头像」开关（默认开）。**

### 背景

Adyeshach 的 NPC 是 **PLAYER 类型实体**，客户端地图原本把它们当作「其他玩家」画头像，
与真人玩家混在一起，无法单独控制。

### 做法

1. **服务端（插件 1.0.4）**：用**反射**调用 Adyeshach（闭源，无法编译期依赖），
   每 2 秒把玩家附近 NPC 的 **UUID** 通过新增的**协议包 11** 下发。
   未安装 Adyeshach 时自动跳过，不影响任何其它功能。
2. **客户端（模组 1.1.13）**：保存这份 UUID 集合；渲染「其他玩家」时先判断——
   **是 NPC 且开关关闭 → 跳过**，真人玩家永不受影响。
3. **两个开关**（默认均为开）：
   * 大地图设置 → `显示 NPC 头像`（`worldmap.showNpcs`）
   * 小地图设置 → `显示 NPC 头像`（`minimap.showNpcs`）
   * 与「显示怪物头像」（MythicMobs）是**两个独立开关**。

### 服务端配置

```yaml
settings:
  npc-track-radius: 128   # 每 2 秒扫描玩家附近此半径内的 NPC
```

## 实测确认（2026-11-22）

在独立 Paper 测试服 + 线上真实 Adyeshach 数据（15 个 NPC）上验证：

| 检查项 | 结果 |
|---|---|
| `AdyeshachHook.isAvailable()` | **true** |
| `getNpcsNear("world", 0,0, 100000)` | **15**（全部 NPC） |
| `getNpcsNear("world", 0,0, 50)` | **0**（半径过滤生效） |
| `getNpcsNear("nonexistent", ...)` | **0**（世界名校验生效） |
| NPC 实体类型 | 全部 `PLAYER` |
| `getUniqueId()` vs `getNormalizeUniqueId()` | **完全相同** |
| StarTrail 启动日志 | 「Adyeshach NPC 同步已启动 (半径 128.0)」「Adyeshach 集成: 已启用」 |

## ⚠️ 已知坑（重要）

**Adyeshach 的 NPC 数据绑定世界名。** 测试时把测试服世界名设为 `testworld`，
15 个 NPC **一个都没加载，且日志里没有任何提示**——非常隐蔽。改成 `world` 后立刻正常。
换世界名时务必留意。

另：Adyeshach 首次启动会联网下载数十个 TabooLib 依赖，耗时约 2 分钟。

## 要不要换 jar

**两端都要换**：

* 客户端 `startrail-forge-1.1.13.jar` → `versions\时之旅者\mods\`（需重启游戏）
* 服务端 `StarTrail-Plugin-1.0.4.jar` → `时旅服务端\plugins\`（**需先关服**）

协议新增类型号 11，老客户端收到会忽略（不影响其它功能），但**看不到 NPC 开关效果**。

## 实机确认清单

1. 两端换到 1.1.13 / 1.0.4，重启服务端与游戏。
2. 打开大地图 → 设置 → 大地图设置：应有三行开关（玩家 / 怪物 / **NPC**），NPC 默认「开」。
3. 切到小地图设置：底部应有 `显示 NPC 头像` 开关，默认「开」。
4. **关掉 NPC 开关** → 地图上 NPC 头像消失，**其他真人玩家头像仍在**。
5. 再打开 → NPC 头像恢复。
