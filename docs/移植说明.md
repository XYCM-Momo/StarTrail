# MMmap Forge 移植说明

> 本文只讲**当初怎么把 Fabric 版移植成 Forge 版**（过程和原理）。
> 日常怎么编译、发布、备份、部署请看 [`../README.md`](../README.md)、[`../VERSIONING.md`](../VERSIONING.md)、[`DEPLOY.md`](DEPLOY.md)。

## 结论先说

工作区里的 **`mmap-fabric-1.9.5.jar`**（原 `mmap-1.9.5.jar`，Fabric / MC 1.20.1 客户端模组）
已经移植成 **`mmap-forge-1.9.5.jar`**（Forge 1.20.1-47.4.10 客户端模组）。

| 文件 / 目录 | 用途 |
|---|---|
| **`dist/client-mod/mmap-forge-1.9.5.jar`** | **成品**：Forge 客户端模组，放进 Forge 客户端的 `mods/` |
| `mod-forge/` | 完整工程源码（Gradle Wrapper 自带，`gradlew.bat build` 即可编译），详见其中的 `README.md` |
| `dist/server-plugin/MMmap-Plugin-1.9.4.jar` | 服务端 Paper 插件，**不用改**，协议与 Forge 客户端完全兼容 |
| `dist/client-mod/mmap-fabric-1.9.5.jar` | 上游 Fabric 版模组（保留基准，不修改） |
| `archive/port-work/` | 移植过程中的工具与中间产物（映射表、反编译源码） |
| `archive/port-work/src-mojmap/` | ★ 移植时对照改写的反编译源码（Mojang 官方命名） |

## 使用前提

* 客户端：Minecraft **1.20.1** + **Forge 47.x**（目标 47.4.10），Java 17。
* ⚠️ `自用客户端` 下的「时之旅者：书启」和 `官方客户端` 都是 **Fabric** 实例（Sodium / Iris / Fabric-API …），
  Forge 模组在 Fabric 里不会生效。本机已有一个 Forge 实例：PCL 版本「**时之旅者**」
  （MC 1.20.1 + Forge 47.4.10），装那里就对了。
* 服务器：继续用 Paper 1.20.1 + `MMmap-Plugin-1.9.4.jar`，无需改动。

## 功能对照（与原版一致）

* 按键：`M` 打开大地图；小地图开关默认未绑定。
* 本地指令：`/mmap crypt`、`/mmap crypt delete`、`/mmap crypt help`
  （别名 `map` / `mmmap` / `minimap`）；`/mmap warp nav|tp <id>` 仍是服务端指令。
* 目录：`<游戏目录>/mmap/{map,legend,mm}`；配置：`<游戏目录>/config/mmap.json`。
* 网络：通道 `mmap:main`，包类型 1~9 与插件 1.9.4 完全一致（字段顺序/编码逐条核对过），
  逐字段对照表见 [`PROTOCOL.md`](PROTOCOL.md)。

## 已做的关键改动（详见 `mod-forge/README.md`）

* 反编译：intermediary → Mojang 官方映射（100% 解析）后反编译，逻辑 1:1 保留。
* 入口/事件：`ClientModInitializer` → `@Mod`、`RegisterKeyMappingsEvent`、
  `TickEvent.ClientTickEvent`、`ClientPlayerNetworkEvent.LoggingOut`、`RenderGuiEvent.Post`。
* 网络：`ClientPlayNetworking` → Forge `SimpleChannel`（把包类型 1~9 注册成消息索引 1~9，
  正好复用插件已有的首字节；注册通道后 Forge 会自动发 `minecraft:register`，Bukkit 才会转发）。
* 指令：原来的 Mixin 拦截 `sendCommand` → Forge 原生 `RegisterClientCommandsEvent`（**已无 Mixin**）。
* 路径：`FabricLoader` → `FMLPaths.GAMEDIR / CONFIGDIR`。

## 上游出新版本时怎么再移植一遍

中间产物都留在 `archive/port-work/` 里，照着走即可：

1. 换掉 `archive/port-work/x-mod/`（新 jar 解包内容）与 `dist/client-mod/mmap-fabric-<新版本>.jar`；
2. 用 `archive/port-work/mappings/` 里的 `intermediary.tiny` + `client-1.20.1-mojmap.txt`
   重新合并出 intermediary→Mojang 的映射（脚本 `archive/port-work/tools/genmap.js`，
   路径已在整理时更新，`node archive/port-work/tools/genmap.js` 可直接跑）；
3. 用 `tiny-remapper.jar` 重映射 → `vineflower.jar` 反编译；
4. 把结果覆盖到 `mod-forge/src/main/java/`（脚本 `archive/port-work/tools/copy-sources.js`
   会自动跳过 `MMmapMod.java`、`MMmapClient.java`、`NetworkHandler.java` 这三个手写过的文件），
   然后**重新把 Fabric API 调用改回 Forge 写法**
   （对照表在 `mod-forge/README.md` 第 5 节；这一步是唯一需要人工的部分）；
5. 改 `mod-forge/gradle.properties` 的 `mod_version`，按 [`../VERSIONING.md`](../VERSIONING.md) 走发布流程。
